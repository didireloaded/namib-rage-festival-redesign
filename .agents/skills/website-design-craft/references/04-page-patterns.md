# Reference 04 — Website archetypes and page structures

These are **starting structures**, not mandatory templates. Choose one primary archetype and adapt. Real brands frequently mix several.

## 1. Marketing homepage

**Goal:** establish relevance, credibility and next action.

Recommended narrative: clear value proposition → proof/demonstration → key use cases or services → differentiated details → authentic evidence → direct CTA.

Hero options: real product in context, high-quality case-study image, video excerpt, editorial split composition, strong type-led value proposition, or interactive product demonstration. Avoid choosing a centered gradient hero by default.

Important states: navigation, responsive CTA, embedded media fallback, form success/error, broken/slow image behavior.

## 2. Creative portfolio / studio

**Goal:** show the work and drive a meaningful enquiry.

Use an image- or film-led visual hierarchy. Curate work rather than displaying dozens of undifferentiated cards. Each project should have a clear title, role, scope, media and outcome where accurate. Optional editorial sequencing can make pages feel authored.

Recommended structures: featured reel or hero work → selected projects → capabilities → approach/people → enquiry; or immediately expose project thumbnails in a distinctive grid with clear labels.

Motion: restrained thumbnail transitions, useful hover previews, shared-element project expansion. Video controls and performance matter. Avoid autoplaying many high-resolution videos at once.

## 3. Event / festival / entertainment

**Goal:** show atmosphere, schedule, credibility and ticket/attendance actions.

Prioritize real photography/video, event date/location, lineup/schedule when confirmed, ticket status, venue information, FAQs and practical logistics. High-impact art direction may use bold color, nonstandard typography and animation, but ticket actions and mobile information must stay clear.

Do not invent artists, sponsors, ticket availability, capacities or testimonials. Distinguish official media from conceptual mockups.

## 4. Hospitality / travel / destination

**Goal:** help guests evaluate and book with confidence.

Lead with authentic atmosphere, location, room/experience details, clear availability path, pricing transparency, policies, maps, accessibility and practical details. Use photography strategically across landscape and portrait formats.

Don't fabricate listings, ratings, reviews, partner affiliations or rates. Booking requests must have truthful availability and payment states.

## 5. E-commerce storefront

**Goal:** help people find, compare, evaluate and purchase products.

Category/product listing: strong filters, sorting, clear prices, inventory status, photo consistency, product titles, pagination/load-more as appropriate.

Product page: gallery, title, variants, stock, price, shipping/returns, primary purchase action, description, sizing/specifications, verified reviews if supplied. Don't hide essential price or shipping details inside a decorative accordion.

Checkout: minimal distraction, clear summary, confirmation of charges, keyboard friendly fields, robust pending/error/duplicate-payment handling.

Motion: small selection/quantity changes, gallery continuity, modest cart feedback; no long checkout animations.

## 6. Service business / agency

**Goal:** explain services, demonstrate capability and generate qualified enquiries.

Lead with what is offered and to whom. Show actual work, service outcomes, proof/portfolio, simple process, trust details, transparent enquiry path. Services can use editorial list rows or thematic sections rather than a generic 3×3 icon card grid.

Forms should ask only for information needed to respond, clarify expected next steps, and actually submit when integrated.

## 7. SaaS / web product

**Goal:** demonstrate value and support evaluation or signup.

Favor real interface captures or interactive demos over decorative pseudo-UI. Explain specific user workflows, integrations that truly exist, security/pricing facts, onboarding needs and credible proof.

Keep supporting technical diagrams simple. Developer features can use genuine code snippets, unlike consumer-facing pages.

## 8. Dashboard / operations console

**Goal:** enable efficient work, not sell the platform.

Prioritize pending work, alerts requiring action, tables/search, filters, accessible numeric summaries, clear row actions, permission-aware views. Avoid tiny 9–11px labels, endless KPI cards, overused glass effects and low-contrast charts.

Desktop can be denser; mobile should prioritize essential tasks rather than squeezing the entire desktop dashboard into cards. Provide accessible data table alternatives where charts are used.

## 9. Editorial / magazine / blog

**Goal:** support reading, finding and understanding content.

Article page: strong title, metadata, lead, comfortable measure, hierarchy, pull quotes sparingly, factual media captions, related reading. Index: category navigation, search, meaningful thumbnails and editorial rhythm.

Avoid defaulting to newsletter popups or moving sidebars that interrupt reading.

## 10. Documentation / help center

**Goal:** help users find accurate information and complete a task.

Use clear hierarchical nav, search, on-page headings, readable code examples where relevant, copy controls, version cues and feedback. Don't hide pages in fashionable but opaque interaction patterns.

Keyboard support, anchors, table of contents and long-form readability are essential. Motion should be minimal.

## 11. Forms / onboarding / booking

**Goal:** move users through a sequence without confusion or data loss.

Provide clear requirements and progress only when steps are genuinely sequential. Use sensible defaults, validation, preserved state, back navigation, clear fee/summary and safe retry. Repeated visitors may need shorter paths.

Do not label a demo booking as real or show a fake confirmation reference. Support interruption, session expiration, file errors and slow network.

## 12. Public service / civic information

**Goal:** improve access to trustworthy information and services.

Emphasize plain language, eligibility, requirements, costs, clear official status, accessible forms, multilingual-ready architecture and robust low-bandwidth behavior. Minimize decorative friction. A site can be visually polished without sacrificing clarity.

## Cross-site navigation patterns

| Complexity | Navigation recommendation |
|---|---|
| Small 3–6-page brochure | Straightforward header, mobile menu, complete footer |
| Medium services/content | Grouped primary nav, clearly labelled subpages, optional search |
| Large commerce/catalog | Category architecture, search, filters, breadcrumbs |
| Dense dashboard | Sidebar/topbar, contextual subnavigation, strong active state |
| Documentation | Sidebar tree, full-text search, on-page section anchors |

Avoid adding a mega menu when there are only five links or burying a large catalogue in a single mobile drawer without search.

## Section composition menu

Choose based on content, not decoration:

- Full-bleed visual with anchored headline
- Editorial split text + genuine image
- Open typographic service list
- Comparison table when choices need comparing
- Timeline for actual chronological/process steps
- Case study with images and results
- Testimonial when sourced and approved
- Interactive demonstration with real behavior
- FAQ for actual recurring objections
- Video player with controls and transcript/captions where relevant
- Product gallery and variant selector
- Accessible chart plus textual interpretation
- Clear contact panel and functional form

Use variety without novelty fatigue. The structure should follow what visitors need to know next.
