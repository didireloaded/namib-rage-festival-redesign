# Ready-to-use IDE prompts

These assume the skill exists at `.agents/skills/website-design-craft/SKILL.md`. Adjust the path for your IDE.

## 1. Plan a new website (no code)

Read `.agents/skills/website-design-craft/SKILL.md` and its relevant references. I want to plan a new website. Study the brief and assets I provide. Create the design thesis, information architecture, sitemap, detailed page blueprint, responsive plan, content and media requirements, proposed components, motion plan and acceptance criteria. Apply the full 20-point anti-slop review. Do not write code yet. Do not invent business facts.

## 2. Design a distinct marketing website

Use `website-design-craft`. Design a visually distinctive, brand-appropriate marketing website. Propose three materially different art directions first if no direction has been approved. For each direction explain typography, colors, page rhythm, hero treatment, photography, navigation, CTA system, motion, mobile adaptation and why it fits the content. Avoid generic gradient hero plus repeated feature card templates.

## 3. Redesign an existing website

Read `website-design-craft`. Audit the current website before changing anything. Identify visual, usability, information hierarchy, responsive, content, accessibility, motion and performance issues. Use the 20 anti-slop checklist with specific evidence and propose prioritized improvements. Preserve working features and approved brand assets. Wait for design direction if I have not selected one.

## 4. Implement an approved website

Read `website-design-craft/SKILL.md`, `03-website-foundations.md`, `05-responsive-accessibility-performance.md`, `06-implementation-recipes.md` and `10-component-states.md`. Implement the approved site with the current framework. Use authentic provided content and assets, functional links/forms, proper loading/error/success states and accessible keyboard/touch controls. Test at 320, 360, 768, 1024 and 1440 widths, plus reduced motion and 200% zoom. Run the anti-slop and QA checks before declaring completion. Report actual tests performed and remaining limitations.

## 5. Add polished website animations

Use `website-design-craft/references/02-motion-20.md` to improve the existing functional website with a restrained animation pass. Select only purposeful transitions for navigation, dropdowns, interactive feedback, galleries and page-state changes. Keep everyday interactions responsive and eliminate bounce on routine controls. Respect reduced-motion settings, focus behavior and performance. Do not redesign unrelated UI.

## 6. Remove AI design slop

Review the current site against all 20 items in `website-design-craft/references/01-anti-slop-20.md`. For each present issue, classify it as justified or unjustified. Provide concrete improvements focused on typography, content, whitespace, section variety, color coherence and real imagery. Do not mechanically remove functional badges, borders or diagrams. Preserve brand-specific choices.

## 7. Portfolio / film / creative studio

Use `website-design-craft` to plan a media-first creative portfolio. Treat authentic projects, photography and videos as the core content. Design distinctive project browsing, clear credits and services, a working enquiry path, restrained video previews, smart responsive crops, captions and reduced-motion behavior. Avoid generic SaaS cards, fake client logos and distracting full-page animations.

## 8. E-commerce or booking site

Use `website-design-craft`. Prioritize discovery, comparison, straightforward selection, accurate prices or availability, checkout/booking clarity, validation and recovery. All transactions must reflect real integrations and server confirmation. Use motion only to show selection and state changes, not to create delays. Review mobile, keyboard and empty/error/duplicate-submit states.

## 9. Dashboard/admin redesign

Apply `website-design-craft` to this dashboard. Preserve data and workflows, reduce over-carded layouts, remove 9–11px text, improve table/filter usability, prioritize pending actions, use semantic status colors and provide accessible dense-data views. Avoid converting every data row into large cards on desktop. Verify keyboard and mobile essential tasks.

## 10. Final design QA

Use `website-design-craft/references/07-review-and-qa.md`. Inspect the current website at actual viewport sizes and verify the primary flows. Report critical/high/medium/low issues, screenshots or observable evidence, fixes made and retests. Do not claim visual or accessibility verification without performing it.
